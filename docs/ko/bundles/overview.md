# 번들

번들은 기존 Spec Kit 확장, 프리셋, 워크플로, 워크플로 스텝 타입을 역할이나 팀을
위한 하나의 버전 지정 설치 가능 구성으로 합성합니다. 번들은 설치할 컴포넌트를
`bundle.yml`에 선언하며, 자체 런타임 동작을 추가하지 않습니다. 각 컴포넌트는
자신의 메커니즘을 통해 설치됩니다.

기능을 추가하려면 확장을, 기존 기능을 사용자 정의하려면 프리셋을, 일련의 과정을
자동화하려면 워크플로를 사용하세요. 이런 조각들을 함께 배포하고 설치해야 할 때
번들을 사용하세요.

> [!IMPORTANT]
> 서드파티 번들과 그것이 설치하는 컴포넌트를 사용하기 전에 검증하세요.
> 커뮤니티 카탈로그는 탐색 채널이지 보안 보증이 아닙니다.
> 메인테이너는 제출 메타데이터의 완전성과 형식을 확인할 뿐, 커뮤니티 번들 코드나
> 그 컴포넌트를 검토, 감사, 보증, 지원하지 않습니다.

## 빠른 시작

번들을 탐색하고 카탈로그 번들이 선언한 컴포넌트를 살펴봅니다.

```bash
specify bundle search
specify bundle info bugfix
```

퍼스트파티 번들을 설치하고, 설치 기록을 확인하고, 제거합니다.

```bash
specify bundle install bugfix
specify bundle list
specify bundle remove bugfix
```

`add`는 `install`의 별칭입니다. 설치는 필요한 경우 Spec Kit 프로젝트를
초기화합니다. 새 프로젝트의 통합을 선택하려면 예를 들어
`--integration copilot`을 사용하세요. 기존 프로젝트의 활성 통합을 전환하지는
않습니다.

직접 작성했거나 검증한 번들이라면 로컬 디렉터리, 매니페스트, 빌드된 아티팩트를
전달하세요.

```bash
specify bundle install ./team-setup/bundle.yml
specify bundle install ./team-setup-1.0.0.zip
```

로컬 소스는 매니페스트를 제공할 뿐, 내장된 컴포넌트 저장소를 제공하지 않습니다.
그 컴포넌트는 여전히 패키지된 자산, 호환되는 설치된 컴포넌트, 또는 각자의
카탈로그로부터 해석되어야 합니다. 커뮤니티 검색 결과 자체가 ID 설치를 허용하지는
않습니다.

## 퍼스트파티 번들

Spec Kit은 `bundles/catalog.json`에서 퍼스트파티 카탈로그를 유지 관리하며, 설치
허용 소스인 `builtin://default`를 통해 노출합니다. 그 항목들은 `verified: true`로
표시됩니다.

| 번들 | 컴포넌트 | 사용 사례 |
| --- | --- | --- |
| `bugfix` | `bug` 확장과 `bugfix` 워크플로 | 안내에 따른 평가, 평가 게이트, 수정, 테스트 |
| `assess` | `assess` 확장과 `assess` 워크플로 | 스펙 주도 개발 이전의 아이디어 분류 |

```bash
specify bundle add assess
```

워크플로를 설치한다고 해서 실행되지는 않습니다. 설치된 구성을 사용하려면
[버그 수정 가이드](../guides/bugfix.md)나
[아이디어 평가 가이드](../guides/assessment.md)를 따르세요.

내장 카탈로그는 온라인에서 가져오며 오프라인에서는 패키지된 스냅샷을 사용합니다.
카탈로그로 탐색한 번들 매니페스트는 퍼스트파티 항목이라도 여전히 네트워크
다운로드가 필요합니다. 로컬 매니페스트는 `--offline`으로 패키지된 컴포넌트를
설치할 수 있습니다. 정확한 한계는 CLI 레퍼런스를 참고하세요.

## 라이프사이클과 소유권

번들은 필요한 컴포넌트와 자신이 기여한 컴포넌트를 모두 기록합니다. 독립적으로
설치된 호환 컴포넌트는 번들 소유가 되지 않고도 요구 사항을 충족할 수 있습니다.
번들을 제거해도 그것은 그대로 남습니다. 다른 번들과 공유되는 컴포넌트는 여전히
필요한 동안 설치된 상태로 남습니다.

변경 없는 설치를 반복하면 기존 컴포넌트와 로컬 편집이 보존됩니다. 소유한
컴포넌트를 다시 적용하려면 카탈로그 릴리스에는 `bundle update <id>`를, 수정된 로컬
소스에는 `bundle install <path> --refresh`를 사용하세요. 업데이트는 전역
트랜잭션이 아닙니다. 이미 설치되어 있던 컴포넌트에 대한 변경은 이후 실패가
발생해도 롤백되지 않습니다.

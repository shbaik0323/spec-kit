# 워크플로 스텝 게시하기

워크플로가 같은 스텝 타입을 재사용할 수 있도록 버전이 지정된 Python 패키지를
게시하세요. 사용자 정의 스텝은 워크플로 정의와 다른 카탈로그 및 제출 계약을
사용합니다.

## 릴리스 준비

일치하는 `step.type_key`와 `StepBase.type_key`, 따옴표로 묶은 PEP 440 호환 버전,
오픈소스 라이선스, 문서를 갖춘 패키지를 제공하세요.
설치, 설정, 의존성, 출력, 실패 동작, 부수 효과, 워크플로 사용 예시를 설명하세요.

유효한 설정과 유효하지 않은 설정, 반환되는 상태, 관련 재개 및 동시 실행 경로를
테스트하세요. `step.yml`과 `__init__.py`가 루트 또는 정확히 하나의 최상위 디렉터리
안에 있는 버전 지정 아카이브를 게시하세요.

소스를 검토한 뒤, 일회용 초기화 프로젝트에서 게시된 아티팩트의 설치를
테스트하세요.

```bash
specify workflow step add my-step \
  --from https://github.com/your-org/my-step/releases/download/v1.0.0/my-step-1.0.0.zip
```

설치는 패키지를 임포트하지 않고 검증하고 복사합니다. 설치된 타입을 워크플로를
통해서도 실행해 보세요. 패키지를 로드하면 Python이 여러분의 권한으로 실행됩니다.

## 커뮤니티 제출

정식 이슈 양식, 버전 지정 아카이브, 태그에 고정된 개별 파일 URL, 파일별
다이제스트, 패키지 한도, 메인테이너가 트리거하는 메타데이터 검증에 대해서는
[커뮤니티 워크플로 스텝 타입 가이드](../community/workflow-steps.md)를 따르세요.

그 이슈 절차를 대신해 손으로 편집한 스텝 카탈로그 PR을 제출하지 마세요.
메인테이너는 제출된 Python 코드가 아니라 메타데이터와 배포 근거를 검증합니다.
커뮤니티 스텝 카탈로그는 탐색 전용으로 남습니다.

## 릴리스 업데이트

패키지 내용이 바뀌면 새 버전을 게시하고, 버전 업데이트와 메타데이터 수정에는 같은
커뮤니티 제출 이슈 양식을 사용하세요. 공개된 과거 릴리스를 보존하세요. 설치된
패키지를 교체하기 전에 소스를 다시 검토하세요. 다이제스트 검사는 바이트를 식별할
뿐, 그 바이트가 안전한지는 알려 주지 않습니다.
